# DevArc QR Invoice

Swiss QR-bill (SIX Swiss Payment Standards) tools for Odoo 19 Community on top of the standard `l10n_ch`
localization. The main feature is the import of vendor QR-bills from the text of a QR code scanner,
a PDF or a photo. On top of that, it adds checks and a clearer message to the QR-bill that `l10n_ch`
prints on customer invoices.

## Features

### Import of vendor QR-bills

- Button *Import QR-bill* on the vendor bill list, menu *Accounting > Vendors > Import QR-bill*, or the
  button *Read QR-bill* on a draft vendor bill.
- Input: the text returned by a QR code scanner (SPC 0200 payload), or an uploaded PDF or photo
  of the QR-bill.
- Only the QR code is decoded, there is no OCR. A PDF is searched on all pages, a document with more
  than one different QR-bill is rejected.
- A QR-bill payable to an IBAN of your own company is rejected, because it is not a vendor bill.
- Filled on the vendor bill:
  - Vendor: found by the IBAN of an existing bank account, otherwise by name and ZIP, otherwise
    created as a new company.
  - Bank account of the vendor (created when missing) and the currency (must be active).
  - Payment reference (QRR or SCOR). The reference *ref* and the bill date come from the invoice
    number (/10/) and the document date (/11/) of SWICO S1 billing information, when present. An
    existing bill date is kept. The unstructured message and billing information go to the notes.
  - One invoice line with the QR-bill amount, quantity 1 and no product. Odoo fills its default expense
    account and the add-on leaves the tax empty, so you choose the account and VAT before posting.
    When the bill already has lines, they are kept and no line is added.
  - The uploaded document is attached to the bill.
  - The bill stays in draft.
- Duplicate warning: Odoo 19 already shows its own duplicate banner on the bill. In addition, when
  another non-cancelled vendor bill of the same vendor and company has the same payment reference and
  the same total in the same currency, or the same invoice number reference, the import shows a
  warning with links to those bills. Some vendors reuse one QR reference on every invoice, so the
  reference alone is not enough. The new bill is created anyway.

### QR-bill on customer invoices

The QR-bill itself is generated by `l10n_ch`. This add-on changes the following:

- With a QR-reference (QRR) or Creditor Reference (SCOR) as payment reference, the *Unstructured
  Message* of the QR code carries the invoice reference or number instead of a duplicate of the
  payment reference. This also applies when `l10n_ch` falls back to a QR-bill without reference (NON)
  because a QRR is used with a regular IBAN.
- Two extra checks: the recipient account must be a CH or LI IBAN and the amount must be between
  0.01 and 999,999,999.99. An invoice that fails a check is printed without the QR-bill page.
- Warning on the customer invoice form that explains why the QR-bill cannot be generated. It is hidden
  on posted invoices that are fully paid.

## Installation

The module needs two Python packages in the Odoo environment:

```
pip install zxing-cpp pypdfium2
```

## Configuration

1. Set the company address (street with house number, ZIP, city, country).
2. Create a bank account with an IBAN or QR-IBAN for the company.
3. For QR-IBAN accounts, set the sales journal reference model to *Switzerland* to generate QR-references.

## Usage

- Vendor bill: press *Import QR-bill* on the vendor bill list, paste the scanner text or upload the PDF
  or photo, press *Import*, then check the draft bill, set the account and VAT and post it.
- Customer invoice: post it with the bank account as *Recipient Bank* and print it. The QR-bill is
  appended as the last page.
